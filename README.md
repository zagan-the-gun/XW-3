# XW-3 出品くん

メルカリ / Yahoo!フリマで**同じ商品を繰り返し出品する**作業を支援するローカルWebアプリ。
商品ごとのタイトル・説明文・タグ・価格・写真を一元管理し、出品時にワンクリックコピー&ドラッグで投入できます。

## 設計方針

- **規約セーフに徹する**: フォームへの自動入力・自動出品はしない。テキストはコピペ、写真はユーザー自身のドラッグ&ドロップで投入し、出品ボタンは必ず人間が押す。
- **データはプレーンなフォルダ**: DB無し。`data/products/<商品名>/product.json` + `photos/連番.jpg`。SMBマウント・バックアップ・git管理が自由。
- **依存ゼロ**: Node.js標準ライブラリのみ。`npm install`不要。

## 起動

### Docker(推奨)

```bash
docker compose up -d --build
```

→ http://localhost:8720 (自宅サーバなら `http://<サーバIP>:8720`)

データは `./data` にマウントされます。

### ローカル(開発時)

```bash
node server.js
```

### 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `8720` | 待ち受けポート |
| `DATA_DIR` | `./data` (Dockerでは`/data`) | データ保存先 |
| `PHOTO_PATH_PREFIX` | (空) | 「写真フォルダのパスをコピー」が返すパスの前置。MacにSMBマウントしている場合は `/Volumes/<共有名>/products` などを設定 |

## 出品時のワークフロー

### A. Chrome拡張を使う(ワンクリック / 推奨)

[`extension/`](extension/README.md) の拡張を入れると、出品ページ右下にパネルが出ます。
商品を選んで「流し込む」を押すと、**写真・タイトル・説明文・価格・各プルダウン**が入ります。
内容を確認して**自分で出品ボタンを押す**だけ。

### B. 手動(拡張なし)

1. 商品を選ぶ → 「出品ページを開く」でメルカリ / Yahoo!フリマのフォームを開く
2. **写真を投入**(下記2方式)
3. タイトル / 説明文 / 価格を「コピー」ボタン → フォームへペースト
4. カテゴリ・商品の状態・配送は画面の表示を見ながらプルダウン選択
5. 出品ボタンを自分で押す

### 写真の投入方式(手動時・検証済み2026-08)

**方式A: フォルダから1ドラッグ(推奨)**
`data/products/<商品>/photos/` をFinderで開き、全選択(⌘A)→出品フォームへドラッグ。
両サイトとも複数枚同時ドロップに対応(Yahoo!フリマは2025-12-17からPCブラウザのD&D対応)。
連番ファイル名なので掲載順も揃います。自宅サーバ運用ならproductsをSMBマウントし、
`PHOTO_PATH_PREFIX` を設定すると「パスをコピー」→Finderで⌘⇧G→ペーストで一発で開けます。

**方式B: 画面から直接ドラッグ(1枚ずつ)**
Chromeは `<img>` を手でドラッグすると**実ファイルとして**ドロップ先に渡します
(Discordなどへのドラッグアップロードと同じ機構)。本ツールの写真サムネイルを
出品フォームのドロップ欄へ1枚ずつ滑らせればマウント不要。**Chrome前提**
(Firefoxはこの機能がデフォルト無効)。

> なお「Webページから複数ファイルを1回のドラッグでまとめて渡す」ことは
> Chromeの仕様上不可能(スクリプトが添付したFileはドロップ時に破棄される)。
> クリップボード経由もPNG1枚ずつが上限。ドラッグ操作自体をなくしたい場合は
> 上記の[Chrome拡張](extension/README.md)を使う。

## サイト別の入力制限(調査値・2026-08)

| | メルカリ | Yahoo!フリマ |
|---|---|---|
| タイトル | 40文字 | 65文字 |
| 説明文 | 1,000文字 | 上限非公表 |
| ハッシュタグ | 説明文内に `#タグ` を記述 | 専用欄(1個30文字・最大20個) |
| 写真 | 20枚 | 20枚 |

本ツールはタグを共通データとして持ち、**メルカリ用コピーでは説明文末尾に自動結合**、
**Yahoo!フリマ用にはタグだけを別コピー**します。文字数カウンタ付き。

## iOSショートカット連携(スマホ出品用・任意)

`GET /api/products/<商品フォルダ名>/photo-urls` が写真の絶対URL一覧をJSONで返します。
ショートカットで「URLの内容を取得」→「辞書の値を取得(urls)」→「各項目を繰り返す」内で
「URLの内容を取得」→「写真アルバムに保存」とすれば、商品の写真をワンタップで
スマホのアルバムに一括保存でき、アプリからの出品で選択できます。

## データ構造

```
data/
  products/
    花ピアス(青)/
      product.json    # 共通(名前・価格・タイトル・説明文・タグ・メモ)
                      # + sites.{mercari,yahoo}.{title,category,condition,shipping}
      photos/
        01.jpg 02.jpg …   # 掲載順の連番
  settings.json       # 全商品共通(送料の負担・発送までの日数・発送元の地域)をサイト別に保持
  trash/              # 削除した商品の退避先(完全削除は手動)
```

カテゴリ・商品の状態・配送の方法は**サイトごとに選択肢の文言が違う**ため、サイト別に保持します。
値は各サイトの画面表記そのままで入力してください(拡張がこの文字列でプルダウンを選びます)。
`GET /api/products/<slug>` の `listing` が両サイト向けに整形済みの値を返し、
**UIのコピーボタンと拡張の自動入力はどちらもこれを使う**ため、内容が食い違いません。

## 注意

- **自宅LAN内での利用を想定**。認証はないため、インターネットへ直接公開しないこと
  (公開する場合は認証付きリバースプロキシの背後に)。
- LAN上のhttpでは `navigator.clipboard` が使えないため、コピーは自動的に
  `execCommand` フォールバックで動作します(実装済み)。
- 短時間に削除→再出品を繰り返す運用はメルカリが迷惑行為と明記しているため非推奨。
  売れた分を補充する通常の出品にはこの制約は関係ありません。
